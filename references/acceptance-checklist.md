# 验收清单（acceptance-checklist）

> 熔炉产物不过闸不交付。P0 全绿是最低交付线；P0+P1 全绿方可发布；P2/P3 按产物定位取舍。
> 分级思路源自归藏 checklist 范式。

## P0 · 致命级（任一不过 = 不能交付）

- [ ] **触发验证**：description 含用户真实说法触发词（中英）；干净环境下用 3 句自然语言提问，模型能正确选中
- [ ] **边界声明**：SKILL.md 有明确"何时不使用"
- [ ] **占位符清零**：产物中无 `[必填]` `[待填]` 类未替换占位符（grep 验证）
- [ ] **真实调用成功**：在至少一个目标平台实际跑通完整流程，产出符合预期
- [ ] **无编造**：产物中无未经来源支撑的事实性内容
- [ ] （改造场景专属）**许可证审查通过**：原作品许可证允许改造分发，产物声明与之一致
- [ ] （改造场景专属）**安全审计通过**：无凭据收集/数据外发/恶意安装器/混淆代码
- [ ] （MCP 专属）`tools/list` 握手正常，每工具至少一个真实用例跑通

## P1 · 严重级

- [ ] **澄清前置**：工作流含澄清步骤，信息不足时禁止猜测开工的指令明确
- [ ] **中间产物**：长流程有落盘校准点（大纲/清单）
- [ ] **防御性检查**：每个易错步骤有显式预检机制
- [ ] **references 按需加载**：详细规范未堆砌在 SKILL.md 主体
- [ ] **验收记录**：《建造档案.md》含本次验收结果
- [ ] （MCP 专属）密钥走环境变量，README 列明所需变量与最小权限

## P2 · 一般级

- [ ] **锚点明确**：审美/质量要求有已知参照物锁定
- [ ] **环境适配分支**：不同 Agent 环境的交互差异显式写明
- [ ] **版本号**：语义化版本，迭代留痕
- [ ] **多平台壳**：目标平台适配按 platform-adapters.md 完成并实测

## P3 · 建议级

- [ ] 来源标注（provenance）完整
- [ ] 更新检查机制（如 git 上游检查）
- [ ] 示例库/效果图集

## 验收流程

1. **自检**：建造者按清单逐项过，记录结果
2. **真实环境跑**：目标平台实测，截图/日志存档
3. **干净环境盲测**：仅装产物、自然语言提问，验证触发与产出
4. **记录**：结果写入产物目录《建造档案.md》（含日期、版本、各平台结果、遗留问题）
