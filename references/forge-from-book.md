# 场景 A：书转技能（forge-from-book）

> 把一本书/一套课程变成 Skill 或 MCP。首个实战样本：梁宁《产品思维30讲》。

## 红线（不可逾越）

1. **必须读原文**：禁止使用 AI 总结版、书评、解读文章作为原料。原文在得到大脑知识库、用户导出的文本或用户提供的文件里。拿不到原文就停下来要，不拿二手材料凑数。
2. **蒸馏不是摘抄**：产物不是书的内容搬运，是把书里的**判断模型**提炼成 AI 可执行的能力点。书是矿石，技能是炼出的金属。
3. **忠实于作者原意**：提炼时不添油加醋；有理解歧义的地方标注，向用户确认。

## 流程

### Step 1 · 获取与通读原文
- 确认原文来源：得到大脑知识库 / 用户上传文件 / 用户口述
- 全书通读，建立结构地图（章→节→核心概念）
- 篇幅过大时分批读，先目录后精读

### Step 2 · 能力点提取（核心环节）
逐章问三个问题：
1. 这一讲教读者**做什么判断/动作**？（不是"讲了什么知识"）
2. 这个判断的**输入、步骤、输出**是什么？
3. **什么时候该用、什么时候不该用**？

产出《能力点清单-v1.md》，每个能力点四要素：

```markdown
## 能力点：{名称}
- 出处：第X讲《{讲名}》
- 何时用：{触发场景}
- 怎么用：{判断步骤/分析框架}
- 判断标准：{怎么算用对了}
- 常见误用：{作者警告过的错误}
```

示例（梁宁30讲）：
- 第2讲同理心 → 能力点"用户情绪地图"：识别用户四种底层情绪（愉悦/不爽/愤怒/恐惧）并据此判断产品机会
- 第10讲机会判断 → 能力点"点线面体分析"：评估一个机会附着在什么经济体上

### Step 3 · 用户确认
把《能力点清单》给用户过目：砍掉的、合并的、优先级排序，都让用户定。**这是质量闸门，不许跳过。**

### Step 4 · 产物判断与建造
- 全书能力点成套、靠提示词生效 → Skill（常见）
- 能力点需配合实时数据/外部动作 → MCP 或 Skill+MCP 混合
- 按 `skill-standard.md` / `mcp-standard.md` 建造
- 书中案例改写为产物的 references 示例（保留出处标注）

### Step 5 · 验收
- 过 `acceptance-checklist.md`
- 专项验收：随机抽 3 个能力点，用真实案例测试产物——模型调用后做出的判断，与书中该讲的判断框架一致

## 常见坑
- **做成知识卡片**：只罗列知识点没有可执行动作——能力点必须动词开头
- **能力点过多**：超过 20 个考虑分层（核心篇/进阶篇）或合并；模型上下文有限
- **丢了书的魂**：作者的核心主张（如梁宁的"产品能力是底层能力"）应写进 SKILL.md 定位段，统摄所有能力点
